# Obsidisync Design Spec

## Overview

Obsidisync is a thin Go server that mounts the user's `Home/Obsidian/` directory from Olares and serves it over WebDAV. Obsidian's Remotely Save plugin connects to it for vault synchronization across desktop, phone, and AI tools.

It is **not** a sync engine. It is a bridge that exposes a filesystem directory over a standard protocol.

## Goals

- Expose multiple Obsidian vaults via WebDAV from a single Olares app
- Work with Obsidian's Remotely Save plugin as the primary client
- Provide token-based auth for machine access (scripts, AI tools, automation)
- Keep the implementation small and auditable
- Avoid coupling to Olares internal storage backends (MinIO, Seahub, Seafile)

## Non-Goals

- Admin UI
- Search or indexing
- Custom sync protocol
- Multi-user support
- Seafile/Sync library integration

## Architecture

### Stack

- **Language:** Go
- **WebDAV:** `golang.org/x/net/webdav` with `webdav.Dir` filesystem backend
- **HTTP:** `net/http` standard library
- **Container:** Multi-stage Docker build → distroless/scratch base (~20MB image)

### Components

```
main.go
├── Auth middleware
│   └── Validates Bearer token on /dav/* requests
├── WebDAV handler (x/net/webdav)
│   └── Rooted at /srv/vault, serves at /dav/
└── Health handler
    └── Serves at /api/health
```

### Graceful Shutdown

The server catches `SIGTERM` (sent by Kubernetes on pod termination) and drains in-flight requests before exiting. This prevents corrupted writes during deployments or restarts.

### Request Flow

```
Client → Olares Gateway (public) → :8080 → Auth Middleware → Route
                                                              ├── /dav/*      → WebDAV handler
                                                              └── /api/health → 200 OK (no auth)
```

## Endpoints

| Path | Method | Auth | Description |
|------|--------|------|-------------|
| `/dav/*` | WebDAV methods | Bearer token | WebDAV root serving mounted vault directory |
| `/api/health` | GET | None | Health check (see response format below) |

### Health Response

- `200 OK` when vault root is accessible and writable:
  ```json
  {"status":"ok","vault_root":"/srv/vault","writable":true}
  ```
- `503 Service Unavailable` when vault root is not accessible:
  ```json
  {"status":"error","vault_root":"/srv/vault","writable":false,"error":"mount not accessible"}
  ```

## Storage Model

### Mounts

| Container Path | Olares Source | Helm Template | Purpose |
|---|---|---|---|
| `/srv/vault` | Home/Obsidian | `{{ .Values.userspace.userData }}/Obsidian` | Vault folders (read-write) |
| `/var/lib/vault-bridge` | appData | `{{ .Values.userspace.appData }}/obsidisync` | Config storage |
| `/var/cache/vault-bridge` | appCache | `{{ .Values.userspace.appCache }}/obsidisync` | Transient cache |

### Vault Organization

Vaults are subdirectories under the mounted root. No registration required — the app serves the entire directory tree.

```
Home/Obsidian/
  ├── personal/     → /dav/personal/
  ├── work/         → /dav/work/
  └── projects/     → /dav/projects/
```

New vaults are created by making a folder in Olares Files under Home/Obsidian/.

### Olares Permissions

```yaml
permission:
  appData: true
  appCache: true
  userData:
    - Home
```

## WebDAV Behavior

### Supported Operations

All handled by `golang.org/x/net/webdav`:

- `PROPFIND` — directory listing, file metadata
- `GET` — read files
- `PUT` — write/overwrite files
- `DELETE` — remove files/folders
- `MOVE` — rename/move
- `COPY` — copy files/folders
- `MKCOL` — create directories
- `LOCK` / `UNLOCK` — in-memory lock system via `webdav.NewMemLS()`

### Built-in Safety

- Path resolution rooted at `/srv/vault` — no traversal outside mount
- ETag support via file modification times
- Last-Modified headers
- In-memory locks (do not survive restarts, not needed by Remotely Save)

### Not Implemented

- Custom sync protocol
- Conflict resolution (Remotely Save handles this)
- File indexing or search
- Persistent lock storage

## Security

### Auth Model

- **v1:** Single global Bearer token for all vaults
- **Future:** Token structure supports adding per-vault scope field
- Token compared using `crypto/subtle.ConstantTimeCompare` (timing-safe)
- Missing or invalid token returns `401 Unauthorized`

### Token Management

- Set via `VAULT_TOKEN` environment variable
- Injected through a Kubernetes Secret (`obsidisync-secret`), referenced via `secretKeyRef` in the deployment
- Token must be at least 32 random bytes, base64-encoded (e.g., `openssl rand -base64 32`)
- Rotated by updating the Secret and restarting the pod
- No rotation API endpoint
- The Secret must be created manually before install (e.g., `kubectl create secret`), or generated by the Helm chart using `randAlphaNum` with a `lookup` guard to avoid regenerating on upgrades

### Path Safety

- `webdav.Dir` roots all filesystem access at the mount point
- Additional `..` component rejection as defense in depth
- App cannot access anything outside the mounted directory

### What the App Does NOT Do

- Use internal Olares service credentials
- Integrate with MinIO, Seahub, or Seafile
- Access arbitrary user directories
- Implement multi-user authentication

## Olares Packaging

### App Identity

- **App ID:** `obsidisync`
- **Title:** `Obsidisync`
- **Icon:** Must be a valid URL (to be provided before packaging — e.g., a PNG hosted on GitHub or a CDN)
- **Port:** `8080`

### Entrance Configuration

- **Auth level:** `public` — intentional; Remotely Save plugin cannot participate in Olares SSO, so the app's own Bearer token is the access control layer. This means the endpoint is internet-exposed; token entropy must be high (32+ random bytes).
- **Name/host:** `obsidisync`

## Client Usage

### Obsidian (Remotely Save plugin)

Each vault's Remotely Save configuration:

- **Type:** WebDAV
- **URL:** `https://obsidisync.<olares-domain>/dav/<vault-folder>/`
- **Auth:** Bearer token (value of `VAULT_TOKEN`)

### Claude / Scripts / Automation

Standard WebDAV or HTTP requests with `Authorization: Bearer <token>` header:

```bash
# List vault contents
curl -X PROPFIND https://obsidisync.<domain>/dav/personal/ \
  -H "Authorization: Bearer <token>"

# Read a file
curl https://obsidisync.<domain>/dav/personal/notes/todo.md \
  -H "Authorization: Bearer <token>"

# Write a file
curl -X PUT https://obsidisync.<domain>/dav/personal/notes/new.md \
  -H "Authorization: Bearer <token>" \
  -d "# New Note"
```

## Acceptance Criteria

### Storage
- App reads/writes only the mounted Obsidian directory
- App cannot access arbitrary user directories
- App config persists in appData

### WebDAV
- Clients can create, update, rename, and delete markdown files
- Directories can be created and browsed
- Markdown files round-trip cleanly
- Multiple vaults accessible as subdirectories

### Security
- `/dav/*` rejects requests without valid Bearer token
- `/api/health` responds without auth
- Traversal outside the vault root is impossible
- App does not use any internal Olares backend credentials

### Olares Integration
- App installs cleanly in Olares
- Public entrance exposes the service
- App ID, deployment, service, entrance names all match (`obsidisync`)

### Usability
- Obsidian Remotely Save can sync through it
- Claude/scripts can read and write files via WebDAV or curl
- Phone access works via WebDAV client or Remotely Save
